Research date: 2026-10-06. Scope: selecting an object of interest and segmenting its visible pixels, including partial visibility, with RGB and ToF. This is a code audit and literature review, not a deployment or model benchmark.

Implementation status, 2026-10-06: the offline stationary diagnostic supports a YOLOE visual reference box, optional initial scene-selection box, optical-flow-assisted identity matching, partial masks, RGB/ToF clipping diagnostics, and frontmost ToF sample selection. The ROS detector/controller no longer restrict the requested class name to bottle or cup: it can select any class emitted by the pinned YOLO11 COCO model. This is class-name detection, not arbitrary visual prompting, and it cannot identify classes outside that model's label set. It reports only fresh mask-associated depth, withholds clearance on clipped/ambiguous contact, and leaves nominal projection unqualified. The visual-reference path remains workstation-only; neither detector has passed a 10-object scene evaluation on the Pi.

The repository contains three different perception paths. The ROS approach runtime accepts a class name from its fixed YOLO11 label set. The workstation diagnostic accepts a free-form text name or visual reference. The older reference-image tool uses a general visual-prompt model but writes a bottle-specific output filename. These paths should not be described as one algorithm.

Both recent diagnostics and the ROS detector use `geometry.Identity`: select the first matching box nearest image centre, then require exactly one box with intersection-over-union at least 0.3. This stores a box, not the target's appearance or segmentation history. A target that becomes heavily cropped, moves after camera tilt, or is hidden can fail this association even if its visible portion remains segmentable.

The named-object diagnostic takes the bottom 10% of mask pixels as candidate floor contact. It records whether any mask edge touches the image boundary, and rejects qualified clearance for any such contact. It can still save a clipped segmentation mask and raw object range percentiles. The edge rule blocks clearance, not segmentation. Bottom-mask pixels are not necessarily floor contact when an object is partially visible, suspended, or lying sideways.

The saved bottle experiment returned no accepted detection at both 640 and 960 input sizes. This establishes failure on that capture at the configured confidence threshold; it does not establish that the target was physically absent or that partial visibility caused the failure. The 960 result is at `/tmp/bottle-segmentation-80deg-960/diagnostic/result.json`. Its image is the same capture as the 640 run, so these are not two independent scene trials.

Partial visibility has three cases: another object hides the target; the target extends outside the image; or the target was identified earlier and only a fragment remains. The third case benefits from temporal memory. A fragment seen for the first time may not contain enough evidence to identify the requested category. A point or box can identify which region to segment, but it does not prove the fragment's semantic identity. No reviewed method guarantees recognition from an arbitrary fragment.

SAM 2 uses streaming memory of prompts and previous predictions, and includes a visibility prediction head. This addresses continuity more directly than matching boxes. Its paper documents failures after long occlusions, among similar objects, and with fine details. It also describes ambiguity between a visible part and its parent object, such as a bicycle tire versus the bicycle. Corrective prompts or reacquisition remain necessary. [SAM 2 paper, model details and limitations](https://arxiv.org/html/2408.00714v2)

My proposed architecture is target selection → acquisition → memory-based visible-mask tracking → calibrated ToF association → measurement quality. Text should support arbitrary names; an optional point, box or example should resolve a specific instance. Preserve an explicit target identity across frames, periodically reacquire, and report visible/partial/lost/ambiguous states. Do not silently switch to another instance when the selected target disappears.

For distance, project native ToF points into RGB using measured camera geometry, resolve competing projected surfaces by visibility, intersect the visible mask, and remove unreliable boundaries/background samples. Depth clustering can propose or refine surfaces, but the nearest cluster must not automatically become the requested object. Camera tilt requires a changing floor model; one fixed distance threshold cannot reliably remove a sloped floor gradient.

Report distance to the observed surface independently from floor-contact clearance. A clipped object can still provide a useful surface measurement if the visible portion has reliable associated depth. Hidden surfaces and missing floor contact remain unknown. An inferred full-object outline must not contribute invented depth samples. The current calibration file leaves RGB/ToF alignment and depth interpretation unqualified, so a better mask alone will not qualify metric clearance.

Recommended evaluation: compare the existing YOLOE baseline, YOLOE acquisition plus SAM 2.1 tracking, and SAM 3.1 where a suitable GPU is available. Use several object categories, multiple similar instances, edge cropping, foreground occlusion, first appearance as a fragment, and full-to-partial-to-hidden-to-visible sequences. Score visible-mask overlap, wrong-instance selection, identity switches, reacquisition, target-absent false positives, measured surface-distance error, and end-to-end frame age. Include the actual RGB640×480 and ToF240×180 modes. Published benchmarks are motivation for this comparison; they do not establish performance on this robot.

The recommendation is an engineering inference from the reviewed capabilities and local failure modes. No replacement model was installed, robot commands issued, or runtime behavior changed during this research.
